# L3·L4 — AEO/GEO 콘텐츠 플레이북 (인용 최적화 본체)

크롤러가 들어오고(L1) 본문이 보인 뒤(L2), **인용될 확률을 실제로 올리는** 레이어.
콘텐츠·문서형 서비스에서 ROI가 가장 높다.

## 0. 답변 엔진이 인용을 고르는 방식 (= RAG 최적화)

AI 답변 엔진은 페이지 전체가 아니라 **패시지(청크)** 단위로 검색·인용한다.

```
질의 → 리트리버가 청크 검색 → 상위 청크만 컨텍스트로 → 생성 → 인용 표기
```

따라서 최적화 대상은 "페이지"가 아니라 **"잘라내도 혼자 말이 되는 문단"**이다.
GEO는 본질적으로 RAG 리트리벌 최적화다. 이 관점 하나로 아래 전술 전부가 설명된다.

## 1. 청크 자기완결성 (Atomicity) — 최우선 원칙

리트리버는 섹션을 문맥 없이 뜯어간다. 그러므로 각 섹션은:

- **대명사로 시작하지 않는다.** "이것은 ~" ❌ → "임신 중 공복혈당은 ~" ✅
- **주어를 반복해서 명시한다.** 앞 문단을 안 읽어도 이해되어야 한다
- **한 섹션 = 한 주제.** 여러 질문을 한 섹션에 섞지 않는다
- 권장 길이 **130~170단어** (한국어 기준 대략 300~450자). 너무 짧으면 근거 부족,
  너무 길면 청크가 잘려 앞뒤가 끊긴다

## 2. 역피라미드 + 직답 블록

각 주요 섹션의 **첫 문단 40~60단어를 그 섹션 질문에 대한 완결된 답**으로 쓴다.
그 뒤에 근거·예외·상세를 붙인다.

```markdown
## 임신성 당뇨 공복혈당 기준은 얼마인가요?

임신성 당뇨의 공복혈당 진단 기준은 92mg/dL 이상입니다. 75g 경구당부하검사에서
1시간 180mg/dL, 2시간 153mg/dL 중 하나라도 넘으면 진단됩니다. (대한당뇨병학회, 2023)

이 기준은 IADPSG 권고를 따른 것으로, ... (근거·예외·상세)
```

- H2/H3를 **질문형**으로 쓴다 — 사용자의 대화형 질의 형태와 일치시킨다
- 답을 결론부터 쓴다. "먼저 배경을 설명하면"으로 시작하는 문단은 인용되지 않는다

## 3. 인용 가능성 신호 (Citation-worthiness)

연구·업계 실측이 반복해서 지목하는 3가지가 **출처 인용·통계·귀속**이다.
이 셋은 상대적으로 낮은 공수로 인용률을 눈에 띄게 올린다.

| 신호 | 구현 |
|---|---|
| **구체 수치** | "혈당이 높으면" ❌ → "공복 92mg/dL 이상" ✅ |
| **출처 귀속** | "(대한당뇨병학회 2023 진료지침)" 형태로 문장 안에 명시 |
| **1차 출처 링크** | 학회·정부·논문 원문으로 아웃바운드 링크 |
| **날짜 명시** | "2026년 기준" 등 본문에 시점을 남긴다 |
| **저자·검수자** | 실명 + 자격 + 프로필 링크 (`Person` 스키마와 연결) |
| **정의 문장** | "X란 ~이다" 한 문장 정의를 각 개념마다 배치 |

## 4. 엔티티 & 권위 (E-E-A-T의 기계 판독 버전)

답변 엔진은 "이 브랜드가 이 주제의 신뢰할 만한 주체인가"를 엔티티 그래프로 판단한다.

- **일관된 표기**: 브랜드명·서비스명을 사이트 전역에서 동일하게 (약칭 혼용 금지)
- **`Organization` + `sameAs`**: 위키데이터·링크드인·공식 SNS·사업자정보로 연결
- **`Person`(저자) + `sameAs`**: 저자별 아카이브 페이지 + 자격 표기
- **엔티티 밀도**: 첫 500자 안에 주제의 핵심 고유명사(질환명·제품명·지역명·기관명)를
  자연스럽게 배치. 리트리버의 임베딩이 주제를 특정하는 근거가 된다
- **YMYL 버티컬(의료·금융·법률)**: 답변 엔진이 극도로 보수적으로 출처를 고른다.
  **권위 기관 인용이 가장 강력한 무기**이며, 면책·검수자 표기가 사실상 필수다

## 5. 구조·형식

| 형식 | 왜 |
|---|---|
| **표** | 비교형 질의("A vs B")에서 통째로 인용되기 쉽다 |
| **번호 리스트** | 절차형 질의("어떻게 하나요")의 정답 포맷 |
| **정의 리스트/용어집** | "X가 뭐야" 질의의 직접 타깃 |
| **FAQ 섹션** | 대화형 질의와 1:1 매칭. `FAQPage` 스키마와 세트 |
| **헤딩 앵커(`id`)** | 답변 엔진이 딥링크로 인용 가능 |
| **이미지 `alt` + 캡션** | 멀티모달 인용 경로 |

멀티모달(텍스트+이미지+영상+구조화데이터) 조합 페이지가 텍스트 전용 대비
선택률이 높다는 업계 측정이 반복 보고된다 — 다만 수치는 벤더 자체 측정이 많으므로
**방향성 근거로만** 취급한다.

## 6. 신선도

- Perplexity 계열은 **신선도 가중이 특히 크다**
- `dateModified`를 실제 수정 시에만 갱신 (허위 갱신은 신뢰 손상)
- sitemap `lastmod` 정확히 유지
- 본문에 "최종 검토: 2026-09" 같은 가시적 시점 표기

## 7. 처방 카탈로그 (impact × effort × confidence)

| 처방 | impact | effort | conf | 비고 |
|---|---|---|---|---|
| 검색계 AI 봇 차단 해제 | 5 | 1 | 1.0 | 차단 중이면 **무조건 1순위** |
| 본문 SSR 전환 | 5 | 4 | 1.0 | CSR이면 다른 모든 것의 전제 |
| JSON-LD 서버 렌더 | 4 | 2 | 0.9 | 클라 주입이면 무효 |
| 질문형 H2 + 직답 블록 | 4 | 2 | 0.85 | 콘텐츠형 최고 ROI |
| 출처·통계·귀속 보강 | 4 | 2 | 0.85 | YMYL에서 특히 큼 |
| `FAQPage` 스키마 | 3 | 1 | 0.8 | 대화형 질의 직접 타깃 |
| `Organization`/`Person` + `sameAs` | 3 | 1 | 0.75 | 엔티티 기반 신뢰 |
| 청크 자기완결성 리라이트 | 4 | 3 | 0.8 | 기존 글 개편 필요 |
| 표·리스트 구조화 | 3 | 2 | 0.75 | 비교·절차형 질의 |
| 신선도 관리 체계 | 3 | 2 | 0.7 | Perplexity 계열에 유효 |
| Markdown 협상 | 3 | 2 | 0.7 | LLM 크롤러 한정. Google 무관 |
| `llms.txt` | 2 | 1 | 0.4 | **효과 논쟁적**. 저비용이라 하는 것 |
| `llms-full.txt` | 2 | 2 | 0.35 | 토큰 예산 없이 만들면 역효과 |
| `Link` 헤더 | 1 | 1 | 0.5 | 저비용·효과 미미 |

`confidence`를 낮게 잡은 항목을 "필수"로 포장하지 않는다. 정직한 기대치가
재측정 단계에서 팀의 신뢰를 지킨다.

## 8. 안티패턴

| 안티패턴 | 왜 나쁜가 |
|---|---|
| 키워드 스터핑 | 답변 엔진은 키워드 밀도가 아니라 의미 정합을 본다 |
| 얇은 페이지 양산 | 청크 품질이 낮아 리트리벌에서 탈락 |
| "결론은 아래에서" 지연 | 직답이 없는 청크는 인용 후보에서 밀린다 |
| AI 생성 대량 문서 | 출처·수치·경험이 없으면 인용 신호가 0 |
| 스키마와 본문 불일치 | 신뢰 손상. 스키마는 **본문에 보이는 내용만** 기술 |
| 크롤러별 다른 본문 | 클로킹. 정책 위반 |
| `llms.txt`에 전체 URL 나열 | 사이트맵 복제일 뿐. 설명 있는 큐레이션이어야 함 |
