# Strategy Brief — 리서치 기반 컨설팅 전략 요약서

리서치 → 추론 → 흑백 컨설팅 PDF 산출까지의 반복 가능한 워크플로우. 결과물은 "신뢰성 있는 컨설팅 펌의 핵심만 담은 요약서" 톤이어야 하며, AI가 만든 티가 나는 화려한 템플릿은 금지한다.

## 결과물 기준 (Non-negotiable)

- **A4, 1~2페이지**로 압축. 지면을 꽉 채우되 과밀하지 않게.
- **흑백 세리프 톤**: 제목은 세리프(Georgia), 본문은 산세리프, 잉크 블랙 + 그레이스케일. 포인트 컬러·둥근 배지·이모지·파스텔 박스 **금지**.
- 구조는 **활자 위계와 얇은 괘선**으로만 잡는다 (번호 인덱스 `01`~`07`, 섹션 구분선).
- 모든 추정 수치에는 **가정(assumption)을 명시**하고 "illustrative/가정 기반 추정"임을 밝힌다. 근거 없는 숫자 = AI slop, 금지.
- 차트/표는 실제 데이터 또는 명시된 가정으로만. 더미면 "예시"라고 라벨링.

## 워크플로우

### 1단계 — 리서치 (Research)
대상(회사·제품·시장)을 다각도로 조사한다. 광범위하면 서브에이전트(web-researcher 등)에 위임해 메인 컨텍스트를 보존.
- **회사**: 공식 사이트를 직접 fetch(검색은 동명 회사 노이즈 주의). 사업영역·대표·지표·대표서비스·고객/실증·특허(Google Patents) 확인.
- **업계·정책**: 최신 동향, 규제/정책 방향(법·제도), 경쟁사 움직임.
- **데이터**: 다룰 수 있는 데이터의 출처·스키마·라이선스·건수를 메타로 정리(별도 METADATA.md 권장).
- 각 주장에 "무엇을 확인했고 무엇은 확인 못 했는지" 구분해서 기록.

### 2단계 — 추론 (Reasoning)
리서치를 종합해 "다음에 뭘 만들어야 하나"를 도출한다.
- 대상의 **강점이 있는 영역 vs 공백(gap)**을 가른다. 공백이 기회다.
- "공공/대기업이 구조적으로 못 하는 것"을 찾는다 (이해상충·수익화 불가·파편화 등).
- 아이디어가 나오면 **반드시 경쟁 조사**: 국내 전업 플레이어 유무 + 해외 성숙 시장 유무. "해외 검증 + 국내 공백"이 가장 좋은 신호.
- 솔직하게 반론한다 — TAM이 작으면 "독립 사업이 아니라 wedge"라고 말할 것. 숫자를 포장하지 말 것.
- (연계) 아이템 자체 발굴·검증이 더 필요하면 `/wj-magic:venture`로, 설계 문서화가 필요하면 `/wj-magic:brainstorm`으로 넘길 수 있다.

### 3단계 — 시장 규모·매출 추정 (Sizing)
`scripts/sizing_template.py`를 복제·수정해 TAM/SAM/SOM과 수익모델별 보텀업 매출을 산출.
- **앵커 수치**는 공개 자료 기반(설비량·시장규모·단가 등), 정밀치 아님을 명시.
- **TAM**(전체 잠재) → **SAM**(유효시장, 비율 가정) → **SOM**(선점 시 점유, 연차별).
- **수익모델별 분해표**: 각 모델의 단가 × 연차별 물량 = 매출. 합계는 반드시 Python으로 검산.
- TAM이 작으면 그 사실 자체가 전략적 함의 — 숨기지 말고 "확장 레버"를 함께 제시.

### 4단계 — PDF 산출 (Build)
`scripts/brief_template.html`을 복제해 내용을 채우고 `scripts/build_pdf.sh`로 PDF 생성.
- 1페이지: 개요(리드) + 7섹션(문제/솔루션/고객·수익/경쟁지형/해자/리스크/다음액션).
- 2페이지(선택): 시장규모(TAM/SAM/SOM 깔때기 + 가정표 + 매출차트 + 수익모델 분해표 + 전략 함의).
- **반드시 PDF를 이미지로 렌더해 눈으로 검증**(`pdftoppm` → 이미지 확인). 스크린샷 뷰포트와 실제 A4 비율이 달라 착시가 생기므로 **PDF 자체를 봐야 한다**.
- 하단 여백이 비면 콘텐츠를 보강하거나 `align-content: space-between`으로 분산. 과밀하면 폰트/간격 축소.

## 레이아웃 핵심 (brief_template.html 기반)

- `.page { width:210mm; height:297mm; display:flex; flex-direction:column; }` + `.page + .page { page-break-before: always; }`
- `.grid { display:grid; grid-template-columns:1fr 1fr; flex:1; align-content:space-between; }` — 2열 신문형, 세로 분산.
- 제목 세리프: `font-family:"Georgia","Times New Roman", ...; font-weight:700;`
- 본문 산세리프: `font-family:"Helvetica Neue","Arial", ...;`
- 섹션 헤더: `01` 인덱스(회색) + uppercase + 하단 1px 괘선.
- 리스트 불릿은 `—`(em dash), 색상 포인트 없음.

## 빌드 명령

```bash
# PDF 생성 (Chrome headless)
bash scripts/build_pdf.sh path/to/brief.html path/to/out.pdf

# 검증용 이미지 렌더
pdftoppm -png -r 110 out.pdf page    # page-1.png, page-2.png
# 그 다음 이미지를 확인해 레이아웃 검증
```

## 금지 사항 (AI 티 제거)

- 파란/보라 포인트 컬러, 그라데이션 라벨 — 금지(별도 다크 대시보드 요청 시에만 예외).
- 둥근 배지 번호, 원형 타임라인 마커, 이모지 섹션 아이콘 — 금지.
- 파스텔 카드 박스 — 금지. 괘선과 여백으로 구조화.
- 근거 없는 수치, 과장된 형용사("혁신적인", "seamless") — 금지.
- 하단이 텅 빈 채로 출력 — 금지. 반드시 PDF 렌더 확인 후 지면 균형 맞출 것.
