# DESIGN 모드 리서치 축 카탈로그

DESIGN 모드는 **아이템이 확정된 뒤** 다각도로 구체화하는 단계다(기존 `ideation`이 하던 일).

## 축은 직군이 아니라 명제다 (B2)

기존 5인 스쿼드(PM/UX/사업/마케팅/데이터)의 실패: 5명에게 "관점"을 주면 **비슷한 시장조사가
5개** 나오고, 아무도 서로의 전제를 확인하지 않는다.

아래 카탈로그는 **관심 영역**일 뿐이다. 워커에게 줄 때는 반드시 **그 영역에서 이 아이템이
성립하려면 참이어야 하는 명제**로 바꿔서 준다.

| ❌ 직군으로 주면 | ✅ 명제로 바꾸면 |
|---|---|
| "PM 관점에서 분석해줘" | "이 카테고리에 국내 직접 경쟁자가 없다는 게 참인가?" |
| "UX 관점에서 봐줘" | "첫 세션 3분 안에 가치를 체감시킬 수 있는가?" |
| "마케팅 전략 짜줘" | "이 타겟은 커뮤니티 인바운드로만 유입된다는 게 참인가?" |
| "수익화 분석해줘" | "월 5~15만원 가격대에서 지불 의사가 실재하는가?" |

축 3~5개를 고르고 **각각을 명제 1개로 변환**한 뒤 fan-out한다(O4).

## 축 카탈로그

### 축 1 — 경쟁·공백 (구 PM)
- 경쟁 제품 5~10개 실검색 확인. **"블루오션"이라는 주장은 반드시 검증한다** — 대개 이미 누가 한다.
- 기능 비교표 + 정직한 공백 지도("A·B는 있음 / C 포맷도 있음 / 이 교집합만 빔").
- 정보 아키텍처 · 핵심 워크플로우 · 사용자 여정.
- MVP → v2 → v3 로드맵.
- **반대 신호(M4)**: 이 공백이 비어 있는 이유가 "수요가 없어서"일 가능성을 먼저 확인한다.

### 축 2 — 사용자 행동·UX (구 UX 리서처)
- 첫 세션 wow moment · 온보딩 마찰 지점 · 이탈 구간.
- 습관 형성 루프(Cue → Routine → Reward), 리텐션 트리거.
- 자기결정이론(자율성·유능감·관계성), Flow, 인지 부하(Miller's Law) 등 근거 있는 원칙 적용.
- **윤리적 설계**: 과몰입 방지, 다크패턴 회피, 결제 유도의 정직성.
- 접근성·포용 설계, 반응형(모바일/태블릿/데스크톱).
- 학술·업계 출처를 명시하고 **근거 등급**을 붙인다.

### 축 3 — 수익 구조 (구 사업 전략가)
- 가격 전략: 패키지·가격대·무료 티어 경계.
- 유닛 이코노믹스: ARPU/take rate · CAC · LTV · 전환율 · 리텐션 · 페이백.
  **LTV:CAC ≥ 3:1** 이상, 2:1 경계, 1 미만 자본 소각.
- 지불 주체가 누구인가(본인/선물/B2B/광고/보험·공단). 불명확하면 감점.
- 전환 퍼널(무료 → 첫 결제 → 반복 → 고가치).
- **go/no-go 게이트**: "이 숫자를 못 넘기면 pivot"을 구체 수치로 건다.
- **명확한 Best Option 1개를 추천**한다. 선택지 나열로 끝내지 않는다.

### 축 4 — 유입·그로스 (구 마케터)
- 0→1 콜드스타트 해법. 공급·수요 중 어느 쪽을 먼저 채우나.
- 채널 우선순위 — **채널을 실명으로**(카페명·커뮤니티명·협회명·검색 키워드).
- SEO 키워드 실검색량, 랜딩 CTA·소셜 프루프.
- 콘텐츠·인플루언서·바이럴 루프(초대 → 보상 → 활성화).
- 출시 전략: 클로즈드 베타 → 오픈 베타 → 정식.
- **반대 신호(M4)**: 이 채널이 이미 포화·차단·유료화되고 있지 않은지 확인한다.

### 축 5 — 기술·데이터 (구 데이터 분석가, `subagent_type: Explore`)
- 기존 코드베이스가 있으면 구조·스택·스키마·외부 연동 현황 파악.
- 새 기능에 필요한 데이터 모델 변경 · API 표면 · 실시간 통신 필요 여부.
- 성능 병목 예측(동시 접속·쿼리·통신 부하).
- **외부 API 의존이 있으면 실제로 호출해 `[실측]`으로 확정한다** — 문서만 읽고 넘어가지 않는다.
- 심화 설계가 필요하면 `db-design` 스킬로 넘긴다.

### 축 6 — 규제·법무 (해당 도메인에 리스크가 있을 때만)
- 인허가·라이선스·신고 의무와 소요 기간.
- 개인정보·미성년·사행성·의료·금융 규제.
- 에스크로·정산·전자상거래 의무.
- **실격 필터 연계**: 인허가 6개월+ 같은 조건은 곧바로 실격 판정으로 이어진다.

### 축 7 — 감각·인격 (디자인 방향이 필요할 때)
- anti-slop 원칙, 제품 인격을 레퍼런스 대비로 정의, 디자인 토큰 최소 스펙.
- 상세 → [craft.md](craft.md). 실제 구현은 `design` / `polish` 스킬로 넘긴다.

## 통합 산출 (전원 완료 후)

```markdown
# {아이템} 통합 스펙 v{N}

## §0 판정 — 이 아이템은 (성립 / 조건부 성립 / 판단 불가)
## 축별 판정 요약 (표: 축 · 명제 · 판정 · 근거 등급)
## 독립 일치 / 충돌 / 뒤집힌 것        ← 리포트 2개 이상이면 필수 (B4)
## 최종 스펙
## 설계 원칙 (근거 명시)
## 수익 구조 + go/no-go 게이트
## 기술 아키텍처 · 데이터 모델
## 유입 전략 (채널 실명)
## 규제 고려사항
## MVP 로드맵 (Phase별)
## 반대 신호 · 남은 [미검증] 항목      ← 생략 금지
```

**"반대 신호 · 남은 미검증"을 빼지 마라.** 그게 다음 라운드의 명제가 된다.

## 전이 규칙

리서치 도중 **축 하나라도 전제가 흔들리면 즉시 INTERROGATE로 전이**한다.
설계를 끝까지 밀어놓고 나중에 뒤집는 것이 가장 비싼 실패다.
