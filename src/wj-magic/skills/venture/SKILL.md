# Venture — 0→1 아이템 발굴에서 감각 디자인까지

막연한 가설 한 줄에서 시작해, **넓게 벌리고 → 데이터로 검증하고 → 냉정하게 죽이고 → 승자를 깊게 파고 → 감각적으로 디자인하고 → 문서로 남기는** 6단계 파이프라인.

이 스킬의 목적은 "그럴듯한 아이디어 하나 뽑기"가 아니다. **틀린 방향을 빨리 죽이고, 진짜 될 것 하나를 근거와 함께 남기는 것**이다. 그래서 이 스킬은 낙관보다 반증에, 아이디어보다 폐기에 무게를 둔다.

## 이 스킬의 영혼 — 7가지 판단 기준 (매 단계 적용)

이건 장식이 아니라 매 단계의 의사결정 렌즈다. 이걸 안 지키면 그냥 평범한 아이디어 브레인스토밍이 된다.

1. **넓게 먼저, 깊이는 나중.** 후보를 충분히 벌리기 전에 하나로 좁혀 세부 질문을 몰아치지 않는다. 이른 깊이는 확증 편향을 부른다. 사용자가 "깊어지기 전에 리스트업부터"라고 말하지 않아도 이 순서를 지킨다.
2. **지적 정직 — cheerleading 금지.** 약한 아이디어는 정직하게 죽인다. "말이 되는 것"과 "혼자 써도 당장 유용한 것"은 다르다. 추정치는 추정이라 명시하고, 반증을 먼저 찾는다. 사용자가 좋아할 답이 아니라 맞는 답을 낸다.
3. **AI 시대 생존 필터.** AI가 죽이는 것(단순 정보·콘텐츠 생성·범용 챗봇·해자 없는 유틸리티)은 후보에서 감점. AI가 못 죽이는 것(네트워크효과·오프라인 이행·신뢰/규제·독점 데이터·하이퍼로컬·결제 레일·사람 연결)에 가점. 상세 → `references/filters.md`.
4. **운영 경량 우선.** 사람 파견·물류·재고·출동이 붙는 무거운 운영은 강한 감점(단, 그게 유일한 해자면 별도 판단). 소프트웨어로 완결되는 구조를 선호한다.
5. **진짜 사업성.** TAM/SAM/SOM, 유닛 이코노믹스(CAC·LTV·전환·리텐션·take rate), 지불 주체가 누구인가, 해자가 무엇인가. "감성 좋다"로 넘어가지 않는다. go/no-go 게이트를 숫자로 건다.
6. **벤치마크 주도.** 미국·일본 등 선진/인접 시장의 검증된 사례를 전수 스캔해 "한국(또는 타겟 시장)에 없거나 약한 것"을 역산한다. 바닥부터 상상하지 않는다.
7. **감각적 디자인 — anti-slop.** 제네릭 AI 룩(보라-파랑 그라디언트·크림+세리프+테라코타·전부 rounded-lg)을 거부한다. 제품마다 고유한 인격(예: "토스는 이런데 우리는 이렇다")과 손끝 감각(모션·마이크로 인터랙션·정보 전달 방식)을 정의한다. 상세 → `references/craft.md`.

## 실행 방식 — 오케스트레이션 우선

각 단계는 **여러 전문가 워커를 병렬로 fan-out**해 실측 리서치를 시키고, 그 결과를 종합해 **발행 아티팩트 1개**로 남긴다. 워커 스폰·재개·수집 패턴은 `references/squad.md`를 따른다.

- 워커에는 항상 강제한다: "WebSearch/WebFetch를 실제로 여러 번 호출하라. 생각만 하고 멈추지 마라. 출처 URL 명시. 추정은 '추정' 표기." (워커가 도구 0회로 조기 종료하면 재개시킨다.)
- 검색 예산 소진 시 WebFetch(DuckDuckGo HTML 등)로 우회하거나, 워커가 새 세션이면 예산이 리셋됨을 활용한다.
- 단계 사이에만 짧게 방향을 확인한다. **질문을 몰아치지 않는다**(기준 1).

각 단계 종료 시 **아티팩트로 발행**하고(디자인 원칙은 craft.md), 사용자가 방향을 정하면 다음 단계로. 산출물은 마지막에 `Ship` 단계에서 프로젝트 문서로 모은다.

## 6단계 파이프라인

### Stage 1 — DIVERGE (벌린다)
막연한 입력(가설·타겟·관심사·또는 무)을 **후보 20~35개로 확장**한다. 절대 한두 개로 좁히지 않는다.

- 입력이 "커뮤니티가 중요하다" 같은 가설이면 → 다양한 고객층/버티컬로 역산.
- 입력이 "이 타겟"이면 → 그 타겟의 지출·페인·트렌드·공급자화·감정 등 여러 각도로 아이템 후보 생성.
- 입력이 없으면 → 시대상·세대별 관심사·매크로 트렌드부터 스캔.
- 병렬 워커로 세그먼트/버티컬을 나눠 리서치. 실 검색량·인구·트렌드 방향을 수집.
- **산출: 후보 전체 리스트업.** 아직 순위·추천을 강하게 밀지 않는다.

### Stage 2 — GROUND (데이터로 검증)
후보들을 **실측 데이터**로 채운다. 각 후보에 대해: 시장 규모 · 커뮤니티/타겟 잠재 규모 · 검색·수요 방향(성장/정체/하락) · 경쟁 포화도 · WTP(지불 의사).

- 병렬 워커로 카테고리별 딥 리서치. 정량 근거 + 출처.
- **산출: 마스터 스코어카드 아티팩트** — 후보 × 지표 매트릭스, 검증(✓)/추정(~) 등급 구분.

### Stage 3 — FILTER (죽인다) ★ 이 스킬의 핵심
5개 킬러 필터(`references/filters.md`)를 **엄격하게** 적용해 대부분을 탈락시킨다. 살아남는 건 보통 1~3개.

- AI 생존 필터 · 운영 경량 · 진짜 사업성 · 경쟁 공백 · 벤치마크 검증.
- **약한 후보는 정직하게 폐기하고 이유를 남긴다.** "두 렌즈(수요 vs 방어력)에 공통으로 살아남는 것"처럼 교차 검증하면 승자가 또렷해진다.
- 사용자가 특정 후보를 좋아해도, 필터에 걸리면 그 사실을 직면시킨다(기준 2). 필요하면 관점을 바꿔 재탐색(벤치마크 각도 등).
- **산출: 승자 후보 + 폐기 근거.** 사용자와 방향 확정.

### Stage 4 — PROVE (딥다이브)
승자 1~2개를 사업으로 성립하는지 깊게 검증한다. 병렬 축(`references/squad.md`의 딥다이브 스쿼드):

- **사업성**: TAM/SAM/SOM · 유닛 이코노믹스 · 3년 시나리오(Bear/Base/Bull) · **go/no-go 게이트**(미달 시 pivot 조건 명시).
- **성공공식**: 인접 마켓플레이스/제품 분해 → 훔쳐올 것 / 피할 함정.
- **UX / CX**: 핵심 화면 흐름 · 온보딩 마찰 제거 · 첫 세션 wow moment · 리텐션 루프.
- **그로스**: 0→1 콜드스타트 · 채널 우선순위 · 바이럴 루프.
- **산출: 마스터플랜 아티팩트.** Conditional GO/NO-GO 판정 + 게이트.

### Stage 5 — CRAFT (감각 디자인)
`references/craft.md`에 따라 제품의 **시각·인터랙션 인격**을 정의한다.

- 무드 디렉션 3안 → 1안 확정 + **디자인 토큰**(색=의미, 타이포, 모션, 질감). anti-slop 필수.
- **제품 인격**을 레퍼런스 대비로 정의("토스는 X, 우리는 Y").
- **손끝 감각**: 정적 시안을 넘어, 핵심 인터랙션을 실제로 만져지는 인터랙티브 아티팩트로.
- **산출: (a) 감각 시스템 아티팩트 (b) 고충실도 핵심 화면 시안.** 시안은 같은 URL로 반복 업데이트.

### Stage 6 — SHIP (정리)
흩어진 산출물을 **프로젝트 문서 구조로 수집**한다.

- 발행 아티팩트 URL 매핑 + 로컬 사본, 리서치 리포트, 폐기 방향 히스토리(판단 근거 보존).
- **8-bit 시각 리포트 생성 + 로컬 오픈 (필수)** — `../../references/common/REPORT_8BIT.md`
  가이드대로 `docs/reports/venture-{아이템}-8bit.html`을 생성하고 `open`으로 브라우저에 띄운다.
  STAGE 구성 예: 후보 도감(카드 그리드) → 필터 게이트(생존/폐기 사유) → 승자 딥다이브 HUD →
  시장 검증 수치 → 감각 디자인 방향 → 다음 액션.
- `docs/` 인덱스(README) 작성. 필요 시 `wj-magic:init`으로 스캐폴드 연계.
- (선택, 사용자 요청 시에만) 리포 네이밍·GitHub 세팅·전략/기술/task 문서.
- **되돌리기 어려운 작업(리포 생성·푸시)은 반드시 상태 확인 후 하나씩.**

## 단계 진행 규칙

- **한 번에 한 단계.** 각 단계 끝에 아티팩트를 발행하고 사용자에게 방향을 확인한 뒤 다음으로.
- 사용자가 "다시", "관점 바꿔서", "이건 별로"라고 하면 → 해당 단계로 돌아가 재탐색. 특히 Stage 3(Filter)에서 되돌아가는 건 정상이고 건강하다. 여러 아이템을 죽이며 수렴하는 게 이 스킬의 정상 동작이다.
- 사용자의 피드백에서 취향을 읽으면 메모리에 저장한다(feedback 타입).
- 병렬 리서치가 도는 동안 사용자에게 진행 테이블을 갱신해 보여준다.

## 관련 스킬과의 관계

- `ideation` — 방향이 정해진 뒤 5인 전문가 스쿼드로 심층 분석(venture Stage 4에서 일부 계승 가능).
- `brainstorm` — 아이템이 대충 정해진 뒤 1:1로 스펙 정제.
- `plan` — 스펙 확정 후 태스크 분해(venture Stage 6 이후).
- `design` / `polish` — UI를 처음 만들거나 다듬을 때(venture Stage 5에서 원칙 공유).

venture는 이들의 **앞단** — "무엇을 만들지 자체가 미정인 구간"을 담당한다.
